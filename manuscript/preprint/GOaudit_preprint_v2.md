# GOaudit: simple taxonomic validation of Gene Ontology (GO) annotations for non-model organisms

**Andreas Bachler**<sup>1,\*</sup>

<sup>1</sup>[Environment, CSIRO, Black Mountain, ACT, Australia]
<sup>\*</sup>Correspondence: Andy.Bachler@csiro.au

**Preprint, 7 August 2026.**

## Abstract

Functional annotation of non-model organisms is now routine, and a wide range of tools is available to assign Gene Ontology (GO) terms to predicted proteomes. These tools differ in evidence and methodology but converge on a common output: a table of protein–GO associations. However, few of these tools are able to verify that the assigned terms are compatible with the taxonomy of the organism under study.

We present GOaudit, a command-line utility that evaluates a protein–GO table against the official GO computed taxon constraints and NCBI Taxonomy for a declared NCBI taxon identifier. It reports a decision and an explicit constraint-based reason for every association, records the provenance of all reference data, and can emit a taxon-filtered table. It is implemented in Python using only the standard library.

We evaluated GOaudit on the 32,879-protein RefSeq proteome of the scleractinian coral *Stylophora pistillata* (GCF_002571385.2, taxid 50429). DeepGOPlus predictions contained 8,316 taxon-incompatible associations (0.759%). InterProScan produced 95,381 associations with 248 flagged (0.260%). eggNOG-mapper run under its own defaults produced 2,160,345 associations, of which 110,903 (5.134%) were incompatible with the coral lineage, affecting 6,169 of 14,571 annotated proteins (42.3%). Flagged terms included mammary gland development, in utero embryonic development, imaginal disc development and chloroplast. A matched option matrix demonstrated that neither annotation scope nor alignment stringency reduced this rate: restricting donor taxa was the only effective control, and it reduced coverage from 14,571 proteins to 164. That restricted configuration contributed little information beyond InterProScan.

Taxonomically implausible annotations can be readily generated by standard annotation workflows and cannot be assumed to be removed by setting more stringent thresholds. A simple, dedicated post-annotation check is inexpensive and removes an identifiable class of error prior to downstream analysis.

**Keywords:** Gene Ontology; taxon constraints; functional annotation; non-model organism; annotation quality control; *Stylophora pistillata*

## Introduction

Functional characterisation of non-model organisms has become widely accessible. Genome assemblies are becoming more accurate, structural annotation pipelines are mature, and a variety of tools exists for inferring function from protein sequence: orthology transfer via eggNOG-mapper [1, 2], protein signature matching via InterProScan [3, 4], phylogenetic placement via TreeGrafter [5], and an expanding family of machine-learning predictors [6–8]. These methods differ in underlying evidence and intended application, but produce a common downstream object — protein identifiers paired with GO terms — which is subsequently used for enrichment testing, comparative genomics and the construction of organism-specific annotation resources.

This convergence is analytically convenient but obscures an important distinction. Functional inference rests on sequence similarity or on patterns learned from annotated reference proteins, and neither establishes that the inferred biological process is realisable in the target organism. Annotation error transferred by homology is well characterised and propagates through sequence databases [9, 10]. The associated risk is greatest under precisely the conditions typical of non-model work: inference across substantial evolutionary distance, sparse representation of the target lineage in reference data, and ontology terms describing anatomical structures or developmental programmes absent from the organism.

GO provides formal machinery addressing part of this problem. Taxon constraints specify that a term is applicable only within a given clade (`in_taxon`) or is prohibited within one (`never_in_taxon`) [11]. A term constrained to Mammalia cannot validly annotate a cnidarian protein. These constraints are released and maintained, and are applied within GO's own quality-control processes [11, 12]. Their availability does not, however, imply that annotation tables produced by external workflows have been evaluated against them.

Several existing tools operate on these constraints. Ontobio and the GO rules framework validate structured GAF and GPAD records in the context of GO data production [13]. The Ontology Access Kit computes inherited constraints for individual ontology terms and supplies the programmatic components of an equivalent audit, although resolution of the target lineage and the join back to annotation rows remain the user's responsibility [14]. FunTaxIS-lite generates taxon-specific prohibited-term lists, extending official constraints with manually curated and annotation-derived rules [15, 16]. Argot2.5 and PANNZER apply taxonomic filtering within their own prediction pipelines [17, 18]. Several of these are more comprehensive in their respective domains. What has been less well served is the common practical case: a researcher holding an arbitrary protein–GO table produced by one or more upstream tools, who requires a portable and reproducible check against a declared organism.

GOaudit has been written to address this specific case. Its stated objective is narrow: to reduce the incidence of demonstrably invalid functional annotations before they enter interpretive analysis.

## Implementation

GOaudit is implemented in Python 3.10 or later using only the standard library. All analyses reported here were performed with version 0.1.0; the audit code is unchanged in the current 0.2.0 release, which adds benchmarks, analysis scripts and documentation. Reference data are managed separately from the package. The `update` subcommand retrieves the GO ontology, computed taxon constraints, taxon groupings and NCBI Taxonomy, recording the source URL, retrieval timestamp and SHA-256 checksum of each file so that a project can pin or archive a specific snapshot.

The `validate` subcommand accepts a tab-separated file containing exactly two columns, `protein_id` and `go_id`, with one association per row, together with an NCBI taxon identifier:

```bash
goaudit validate annotations.tsv --taxid 50429 --output-dir results --mode report
```

The restrictive input contract is intentional. Additional columns, comma-separated GO lists and malformed identifiers are rejected, ensuring that parsing problems are surfaced before any filtering occurs. Converters for eggNOG-mapper and InterProScan output are provided for convenience; any workflow capable of emitting the two required columns can be audited.

GOaudit resolves the complete NCBI lineage of the target taxon, mapping merged taxon identifiers to their current form. Alternate GO identifiers are resolved to their primary terms. Each resulting term is evaluated against the constraints materialised in GO's computed constraint file, with union taxon classes expanded from the released grouping file. Obsolete terms and identifiers absent from the selected ontology release receive distinct statuses rather than being discarded or misclassified as taxon violations, maintaining a separation between ontology-version maintenance and taxonomic filtering.

The default `report` mode is non-destructive. It writes `audit.tsv`, containing the resolved identifier, term name, namespace, status, applicable constraint and explanatory reason for every input row; summary statistics in tabular and JSON form; diagnostic plots; and `reference_manifest.json` recording the exact reference data used. The `flag` mode appends status columns to the input associations, and `remove` mode writes a filtered two-column table excluding taxon violations only. This report-first default reflects the interpretation of a flagged association as a reproducible indication for review rather than as established error.

Because GO releases change, results are interpretable only in conjunction with the GO release, taxon identifier, software version and mode used to generate them; each run records these values.

### Preparation of organism annotation databases

Enrichment analysis within the Bioconductor ecosystem requires an `OrgDb` package, which does not exist for most non-model organisms. The optional `prepare-orgdb` subcommand supports this requirement. It validates an EGAPx or RefSeq-style GFF3 gene–transcript–CDS hierarchy, verifies `protein_id` mappings, reports mapping coverage and identifier collisions, and terminates on ambiguous protein-to-gene assignment. It emits validated tables suitable for `AnnotationForge::makeOrgPackage()`. Construction of the R package remains a separate workflow, documented at `docs/orgdb-workflow.md`. This has been added to assist researchers in quickly moving from GO term validation to analysis with various Bioconductor packages.

## Results

All analyses used the RefSeq proteome of *S. pistillata* (assembly GCF_002571385.2, NCBI taxid 50429; 32,879 protein sequences), audited against the 15 June 2026 GO release. Three annotation workflows were applied to the identical FASTA file.

### Annotation workflows differed markedly in coverage and taxonomic compatibility

InterProScan 5.72-103.0 assigned 95,381 associations to 23,338 proteins (71.0% of the proteome) across 5,375 GO terms. GOaudit flagged 248 associations (0.260%) affecting 212 proteins. Protein-signature matching performs sequence-level validation, and the resulting low violation rate is consistent with that.

DeepGOPlus 1.0.2, applied at combined scores ≥0.30, produced 1,095,349 associations across 31,035 proteins (94.4%). GOaudit identified 8,316 incompatible associations (0.759%) spanning 1,202 terms and 1,285 proteins. Increasing the score threshold did not proportionally reduce this: 2,306 incompatible associations were retained at scores ≥0.65.

eggNOG-mapper 2.1.12 is the only one of the three workflows exposing explicit taxonomic controls, and was therefore examined in detail.

### Alignment stringency and annotation scope did not affect taxonomic compatibility

A matched option matrix was constructed on the same proteome (Table 1). Two DIAMOND searches were performed — one using eggNOG-mapper defaults (28,670 seed orthologs) and one applying stringent filtering at E ≤ 1×10<sup>-10</sup>, bit score ≥60, identity ≥40% and query and subject coverage ≥50% (15,848 seed orthologs). Eight annotation passes then reused these seed tables via `-m no_search`, allowing search stringency and donor policy to be varied independently.

**Table 1. eggNOG-mapper option matrix.** Coverage is expressed relative to 32,879 input proteins; violation and obsolescence percentages are relative to each run's own associations.

| Search | Annotation options | Proteins | Coverage | Associations | Taxon-incompatible | Obsolete |
|---|---|---:|---:|---:|---:|---:|
| Defaults | eggNOG-mapper defaults | 14,571 | 44.3% | 2,160,345 | 110,903 (5.134%) | 328,694 |
| Defaults | `--go_evidence all` | 15,893 | 48.3% | 2,353,479 | 113,013 (4.802%) | 368,014 |
| Defaults | `--tax_scope Metazoa`, donors unrestricted | 14,606 | 44.4% | 2,235,546 | 109,490 (4.898%) | 347,677 |
| Defaults | Donors Metazoa excluding Bilateria | 164 | 0.50% | 8,155 | 0 (0%) | 1,990 |
| Defaults | Donors Cnidaria, all evidence | 156 | 0.47% | 7,705 | 0 (0%) | 1,866 |
| Defaults | Donors Cnidaria, non-electronic | 112 | 0.34% | 3,633 | 0 (0%) | 926 |
| Stringent | eggNOG-mapper default annotation | 9,595 | 29.2% | 1,432,157 | 66,570 (4.648%) | 226,354 |
| Stringent | Donors Metazoa excluding Bilateria | 137 | 0.42% | 6,852 | 0 (0%) | 1,807 |

Under default settings, eggNOG-mapper annotated 14,571 proteins with 2,160,345 associations, of which 110,903 (5.134%) were incompatible with the coral lineage. These violations spanned 2,968 distinct GO terms and affected 6,169 proteins, or 42.3% of all proteins the workflow annotated. A further 328,694 associations (15.2%) used terms obsolete in the audited GO release, reflecting the age of the eggNOG 5.0.2 annotation payload relative to the current ontology.

The flagged terms were not marginal cases. The most frequent were circulatory system development (1,797 associations), central nervous system development (1,505), head development (1,262) and brain development (1,186). Also represented were in utero embryonic development (537, constrained to Theria), salivary gland development (262, Bilateria), mammary gland development (197, Mammalia), prostate gland development (157, Mammalia), imaginal disc development (733, Insecta) and instar larval or pupal development (718, Arthropoda). A smaller set violated `never_in_taxon Metazoa`, including chloroplast (11) and plastid (12). These terms describe mammalian reproductive and glandular structures, insect metamorphosis and plastid compartments, none of which are realisable in a scleractinian coral.

Two configurations that might be expected to mitigate this had negligible effect. Specifying a Metazoa annotation scope without restricting donors changed the violation rate from 5.134% to 4.898%. Stringent alignment filtering was applied aggressively, removing 44.7% of seed orthologs and reducing annotated proteins from 14,571 to 9,595, yet reduced the violation rate only to 4.648%. Admitting electronically inferred terms increased coverage to 15,893 proteins without materially altering the rate (4.802%). This result is mechanistically unsurprising: alignment stringency establishes that a sequence match is genuine, but carries no information regarding whether the matched protein's annotated function is transferable to the target lineage.

Donor restriction was the only effective control, and its effect was close to binary. Restricting annotation donors to non-bilaterian Metazoa (`--target_taxa 33208 --excluded_taxa 33213`) eliminated all violations while reducing coverage from 14,571 proteins to 164, an 89-fold reduction. Cnidaria-only donor pools yielded 156 and 112 proteins under all-evidence and non-electronic policies respectively, likewise without violations.

### The taxonomically compatible configuration contributed limited additional information

Because donor restriction produced the only formally compatible eggNOG-mapper output, its information contribution relative to InterProScan was quantified on the same proteins (Table 2). eggNOG-mapper propagates GO ancestors whereas InterProScan reports signature-level mappings, so exact association matching understates agreement. Overlap was therefore also evaluated under ancestor closure over `is_a` and `part_of`, counting an eggNOG-mapper association as covered when its term was an ancestor or descendant of an InterProScan term on the same protein. The residual eggNOG-mapper-only set was stratified by ontology depth, defined as the shortest path from the namespace root, with depth ≥5 adopted as a pragmatic threshold for terms sufficiently specific to support interpretation.

**Table 2. Information contributed by eggNOG-mapper relative to InterProScan.** Usable associations only (GOaudit status `valid` or `alternate_id`).

| Measure | Restricted donors | Defaults |
|---|---:|---:|
| Usable associations | 6,048 | 1,683,713 |
| Proteins annotated | 164 | 14,571 |
| Proteins also annotated by InterProScan | 135 (82.3%) | 12,874 (88.4%) |
| Proteins not annotated by InterProScan | 29 | 1,697 |
| Covered under ancestor closure | 3,347 (55.3%) | 363,687 (21.6%) |
| eggNOG-mapper-only | 2,701 (44.7%) | 1,320,026 (78.4%) |
| eggNOG-mapper-only and specific (depth ≥5) | 583 (9.6%) | 455,913 (27.1%) |

Of the 164 proteins annotated by the restricted configuration, 135 (82.3%) were already annotated by InterProScan. Under ancestor closure, 3,347 associations (55.3%) were already implied by an InterProScan term on the same protein. Of the remaining 2,701 eggNOG-mapper-only associations, the majority were near the ontology roots; only 583 (9.6% of usable output) reached depth ≥5, spanning 190 terms and 104 proteins. Of the 135 proteins annotated by both workflows, 58 gained no specific term from eggNOG-mapper. Specific contributions were present but infrequent, including 2',3'-cyclic GMP-AMP synthase activity on 18 proteins.

The default configuration exhibited the inverse behaviour. Following removal of all taxon violations, it retained 455,913 specific associations not implied by InterProScan, distributed across 12,991 proteins and including 1,697 proteins InterProScan did not annotate. Orthology transfer can therefore contribute substantially to a non-model proteome, but under the reference releases examined here that contribution is available only in the configuration that also generates the 5% incompatible fraction.

## Discussion

Three observations follow from these results.

First, the workflows providing most of the annotation coverage offer no taxonomic control. InterProScan covered 71.0% of the proteome at a 0.260% flag rate and DeepGOPlus 94.4%; neither exposes taxonomic configuration, and neither structurally could, since a signature match and a learned label carry no representation of the query's lineage. eggNOG-mapper is the only workflow examined with donor controls, and on this proteome it contributed least. Upstream configuration therefore protects only a limited portion of a typical annotation set, and an external check is the sole available control for the remainder.

Second, correct taxonomic configuration of eggNOG-mapper represents a genuine trade-off rather than an unambiguous improvement. The donor-restricted configuration is formally compatible but annotated 0.50% of the proteome and contributed little beyond InterProScan. This reflects the sparse representation of non-bilaterian metazoans carrying curated GO annotations in eggNOG 5.0.2, rather than a deficiency of the software; a future release with improved cnidarian coverage would shift the balance.

Third, and most importantly, these results do not support permissive annotation followed by taxonomic filtering as a substitute for appropriate upstream configuration. Taxon constraints are defined for a minority of GO terms. Filtering removes formally incompatible associations while leaving a larger class that is taxonomically permitted but evolutionarily unsupported: a term transferred from a distant bilaterian orthologue lacking a coral counterpart will typically carry no constraint. The 5.134% reported here is a detectable lower bound on transfer error, not an estimate of its magnitude. A default run followed by an audit is not equivalent to a donor-restricted run, since the two procedures remove different and only partially overlapping sets of associations.

The contribution of the audit is correspondingly bounded. It establishes a reproducible, release-anchored floor beneath an annotation set, preventing terms such as mammary gland development and chloroplast from reaching enrichment analysis. It does not establish that the remaining annotations are correct.

The following workflow is recommended:

1. Configure each annotation tool as fully as its own options permit, including taxonomic scope and donor controls where available.
2. Retain original outputs, command lines and database or model versions.
3. Convert associations to one protein–GO pair per row.
4. Run GOaudit in `report` mode with the target organism's NCBI taxon identifier.
5. Review recurrent and high-impact violations before removing any association.
6. Apply `remove` mode only following that review.
7. Retain the reference manifest and use an identical gene universe before and after filtering.

## Limitations

GOaudit detects only those constraints encoded in the GO release supplied to it. A term biologically implausible for the target organism but carrying no formal constraint will pass validation. This is the principal limitation of the approach and the reason it complements rather than replaces appropriate upstream configuration.

Constraints may themselves be erroneous or temporarily inconsistent. In the InterProScan audit, 16 `syntaxin binding` associations inherited an `in_taxon Bacteria` constraint despite the term's established use in eukaryotic annotation; the parent term carries an open GO tracker item. Such cases warrant reporting to the GO Consortium rather than automated removal, and motivate the non-destructive default mode.

The two-column input format does not preserve annotation source, evidence code or confidence score. This supports interoperability but requires that users retain original outputs independently.

The depth ≥5 threshold used to characterise annotation specificity is a pragmatic convention rather than an established measure. The case study comprises a single proteome and does not estimate error rates across taxa or predictors. The InterProScan release used (5.72-103.0) was the archived installation available on the compute system rather than the current release, and its counts should not be extrapolated to newer versions.

Finally, GOaudit evaluates annotations rather than gene models. Chimeric or fragmented protein predictions may carry taxonomically valid GO terms [19].
